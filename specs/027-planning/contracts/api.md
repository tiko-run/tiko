# API: planning

Instance data. Reading needs a signed-in person (a public link viewer gets the names through the board's own payload, see below). Writing needs a person with an account who is not a demo visitor; the switch needs an admin. Errors as in the rest of the API: `401`, `403`, `404`, `422`.

## `GET /api/planning`

```json
{
  "enabled": true,
  "types": [{"id": "t1", "name": "Discovery", "hue": 75, "archived": false}],
  "people": [{"id": "p1", "name": "Anna", "teams": ["Core"], "source": "manual", "archived": false,
              "off": [{"id": "o1", "start": "2026-10-05", "end": "2026-10-09"}]}],
  "fields": [{"id": "priority", "name": "Priority", "standard": true},
             {"id": "f7", "name": "Quarter", "standard": false}],
  "views": [{"id": "v1", "name": "Web in Q4", "filters": {"team": ["Web"], "f7": ["Q4"]}}],
  "daysOff": ["2026-11-04"]
}
```

One read for everything a Gantt needs. With Planning off, and always on a demo instance, it answers `{"enabled": false}` and the rest empty; `PATCH` and every write are `403` on a demo instance. `source` is `manual` or `tracker`. `hue` is one of 25, 60, 75, 150, 200, 250, 300, 340. Standard fields are `priority`, `size`, `team` and cannot be removed. Ids are generated by the server.

## `PATCH /api/planning`

`{"enabled": true}`, admins only. The first time Planning is turned on the five default types are created.

## Types, people, fields, views

| Method and path | Body | Notes |
|---|---|---|
| `POST /api/planning/types` | `{"name", "hue"}` | name 1–40 characters, unique among active types |
| `PATCH /api/planning/types/{id}` | `{"name"?, "hue"?, "archived"?}` | |
| `POST /api/planning/people` | `{"name", "teams"?, "source"?}` | name 1–80; up to 10 teams of up to 40 |
| `PATCH /api/planning/people/{id}` | `{"name"?, "teams"?, "archived"?}` | |
| `POST /api/planning/people/{id}/off` | `{"start", "end"}` | up to 100 ranges per person |
| `DELETE /api/planning/people/{id}/off/{offId}` | | |
| `POST /api/planning/fields` | `{"name"}` | name 1–40, unique; up to 50 fields |
| `PATCH /api/planning/fields/{id}` | `{"name"?, "archived"?}` | standard fields: name only |
| `POST /api/planning/views` | `{"name", "filters"}` | up to 100 views |
| `DELETE /api/planning/views/{id}` | | |
| `PUT /api/planning/days-off` | `{"dates": [...]}` | up to 400 dates |

Each answers with the created or changed object. A change is broadcast to every open board as a `planning` live event, so other people's Gantts refresh their lists.

## `GET /api/planning/people/{id}/workload?from=2026-10-12&weeks=12`

```json
{
  "weeks": [{"start": "2026-10-12", "stages": 2, "overlap": true, "off": false}],
  "stages": [
    {"board": "b1", "boardName": "Payments", "row": "Payment API", "type": "t3",
     "start": "2026-10-19", "end": "2026-11-27"},
    {"board": null, "boardName": null, "row": null, "type": null,
     "start": "2026-10-26", "end": "2026-11-06"}
  ]
}
```

A stage on a board the reader cannot open has `board`, `boardName`, `row` and `type` set to `null`. `weeks` is at most 26.

## Public link

A board's public payload carries the names and type colors used on its Gantts (`planning: {types, people}` limited to the ids on that board), so a viewer sees stages and names without access to the directory.
