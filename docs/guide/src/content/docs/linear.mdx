Linear issues become live cards on any tiko. Each person connects their own Linear API key, so a card shows only what that person can see in Linear. Nothing is set up in tiko. In Linear, members can create API keys unless a workspace admin has turned that off; then ask the admin to allow it.

## Your API key

<Steps>

1. In Linear, open **Settings → Security & access** and create a personal API key. Read access is enough: tiko never changes anything in Linear.
2. In tiko, open **Settings → My tracker**, paste the key into **Linear API key** and save. tiko checks it with Linear first and answers with your name and workspace.

</Steps>

The key stays on the server, encrypted, and is only ever sent to `api.linear.app`. Remove it in the same place.

A Linear key reads one workspace. Linear counts 2,500 requests and 3,000,000 complexity points an hour for each person, shared by all their keys and tools; tiko keeps a tenth of each free and waits until the reset Linear reports rather than use them up.

## Add a card

Copy the link of an issue in Linear and paste it on the board with `⌘V` (`Ctrl+V`), or pick the card tool (`C`) and paste the link there. Typing just `ENG-12` works too, and so does `your-workspace/ENG-12`. Several at once work too. All the forms are in [What you can add](../what-you-can-add/#linear).

## Bare identifiers

A bare `ENG-12` goes to the tracker that knows `ENG`: Linear when one of your teams has that key, Jira when it is one of its projects. When both know it, tiko asks where `ENG-12` is from, once per prefix in a paste of many. Tick **Remember for ENG** and the next `ENG` key goes there without a question.

Your remembered choices are listed in **Settings → My tracker → Key prefixes**, where you switch or remove each one. Scripts and AI agents that add an ambiguous key are told to write `jira:ENG-12` or `linear:ENG-12` instead.

## Many issues by a query

Fill a board from a cycle, a project or a label in one go. Pick the card tool (`C`), open its **Linear** tab and write a query the way you would in Jira:

```
team = ENG AND cycle in openSprints() AND assignee = currentUser()
text ~ "billing" AND updated > -2w
```

Suggestions offer the fields, then the teams, projects, cycles, statuses, labels and people of your workspace. Up to 50 issues come in at once, newest change first; when more match, the tool says so and you narrow the query. A link to a saved view in Linear works in the same field and adds the view's issues.

| Field | Operators | Values |
|---|---|---|
| `team` | `=` `!=` `IN` `NOT IN` `~` | The team's key or name |
| `project` | `=` `!=` `IN` `NOT IN` `~` `IS EMPTY` | Its name |
| `cycle` | `=` `!=` `IN` `NOT IN` `IS EMPTY` | Its number or name, `openSprints()`, `nextSprint()` |
| `status` | `=` `!=` `IN` `NOT IN` `~` | Your workflow state's name |
| `statusCategory` | `=` `!=` `IN` `NOT IN` | `"To Do"`, `"In Progress"`, `Done` |
| `assignee`, `reporter` | `=` `!=` `IN` `NOT IN` `~` `IS EMPTY` | A name or e-mail, `currentUser()` |
| `labels` | `=` `!=` `IN` `NOT IN` `~` `IS EMPTY` | A label's name |
| `priority` | `=` `!=` `IN` `NOT IN` | `Urgent`, `High`, `Medium`, `Low`, `"No priority"` |
| `created`, `updated`, `due` | `>` `>=` `<` `<=` (`due` also `IS EMPTY`) | A date like `2026-11-30`, or `-2w`, `-3d`, `1M` from now |
| `text` | `~` | Words in the title or the description |
| `title` | `=` `!=` `~` | The title |
| `key`, `parent` | `=` `!=` `IN` `NOT IN` (`parent` also `IS EMPTY`) | An identifier like `ENG-12` |

Join conditions with `AND`, `OR` and parentheses. `labels != bug` also matches issues without labels, as Linear's own "is not" does. `NOT (…)` and `ORDER BY` are not read; a query tiko cannot read says where and what it expected.

## Read a card

- **On the board:** the identifier like `ENG-12`, the title and the status, in the color of its kind: not started, in progress or done.
- **The mini-card**, on click: the assignee, the priority, the labels as chips in their Linear colors, the project, the cycle, the estimate, the parent issue of a sub-issue, and a link to Linear.
- **On a Gantt:** an issue's due date is where its bar ends.

## Statuses

The card shows your workflow state by its own name. Its color comes from the kind of state:

| Kind of state in Linear | On the card |
|---|---|
| Triage, Backlog, Unstarted | Not started |
| Started | In progress |
| Completed, Canceled, Duplicate | Done |

## Who sees what

- **You** see your Linear cards in full.
- **A teammate** on the same board sees them only with a key of their own; without one a card shows its identifier and asks them to connect Linear.
- **A guest** of a public link sees the identifier and a link to Linear, never the title.
